# Secret & Identity Key Architecture (Approach 1: hybrid)

Goal: make all SSH/identity key distribution and sops-age secret rotation
**declarative, in-repo, no host shelling**, and eliminate the
`ssh builderX` "accept host key? (y/N)" prompt by pre-populating
`known_hosts` from keys declared in this repo.

Status: **design — not implemented. Awaiting review before planning.**

## 1. Problem & current state (from repo)

- `modules/common/distributed-builds.nix` (imported by every host via
  `modules/common`): enables `nix.distributedBuilds = true`, sets
  `nix.buildMachines = [builder1..builder4]`, and `programs.ssh.extraConfig`
  maps `Host builderN` → `HostName`/`User remotebuild`/`IdentityFile /root/.ssh/remotebuild`.
  Builder identity `remotebuild` priv/pub come from `sops.secrets."remotebuild/key"`
  and `"remotebuild/pub"` (decrypted under `/root/.ssh/`).
- **No `services.openssh.knownHosts`** anywhere → every builder connects to an
  unknown host key → interactive `yes`.
- **No `security.ssh.hostKeys`** anywhere → host keys auto-generated by nixos,
  pubs never declared → same trust gap, and rotation means `rm /etc/ssh/ssh_host_*`+rebuild.
- Builders are hardcoded to `builder1..builder4` (10.0.0.3, 10.0.0.7, woody.fritz.box, 10.0.0.10); slinky overrides its own list; `woody` sets `distributedBuilds = false`.
- Existing identity pattern (cited as the model): borg client key lives as
  `sops.secrets."borg/<repo>"` (priv, per-host `secrets.yaml`) referenced by
  `BORG_RSSH="ssh -i ${...path}"`; the matching pub is committed **plaintext**
  in `modules/borg-server.nix` `authorizedKeysAppendOnly`.

Conclusion: the repo already keeps **pubs plain in config, privs in sops-per-host**.
The architecture extends that pattern from "borg pubs" to **all host identities**
and adds the missing `knownHosts` step.

## 2. Design: separation of concerns

Two kinds of key material, two mechanisms:

| material | what it is | where it lives | mechanism |
|---|---|---|---|
| **Identity keys** (host SSH keys, borg client keys, builder identity, nebula peer keys) | pub is public | pub: committed plaintext in repo; priv: sops-per-host | `security.ssh.hostKeys` / `authorizedKeys` / `knownHosts` / `BORG_RSH` read from sops path + `lib.fileContents(pub)` |
| **Secret data** (bot tokens, TLS privkeys, nebula certs/keys, TOTP seeds) | must stay encrypted | sops-per-host `secrets/hosts/<host>/secrets.yaml` | `sops.secrets.<name>.path`, unchanged |

Identity keys rotate via nixos-rebuild (regenerate pair → redeploy).
Secret *data* rotates via the rotate script §6. Age-key rotation of a host's
own file is the per-host case in §6.3.

## 3. Identity key schema (uniform)

A host identity key = **one sops secret (priv)** + **one committed pub file**,
named by a small convention so all consumers agree:

```
secrets/common/ssh/<host>/<label>.pub   # plaintext, committed (eval-time lib.fileContents)
secrets/hosts/<host>/secrets.yaml       # sops — priv lives here under key "<label>.key"
```

Convention:
- `<host>` = `config.networking.hostName`.
- `<label>` = `"ssh"` (host key), `"build"` (nix build identity), `"borg:<repo>"` (borg client key). Pub files for borg client keys are owned by the *client* host (the host that backs up), read by the *server* host's `borg-server.nix`.
- Priv path in sops → `sops.secrets."<label>.key"`, with an explicit `path`
  (e.g. `/etc/ssh/ssh_host_ed25519_key` for host keys; `/root/.ssh/remotebuild` for build identity).

`lib.fileContents ../../secrets/common/ssh/<host>/<label>.pub` is safe at eval
(it reads a committed file). This is how `knownHosts` + `authorizedKeys` +
`borg-server` get pubs without touching any host.

### 3.1 Host SSH host keys
```
security.ssh.hostKeys = [ {
  type = "ed25519";
  path = config.sops.secrets."ssh.key".path;   # /etc/ssh/ssh_host_ed25519_key
} ];
```
- Openssh will also look for the sibling `.pub`; if absent it regenerates a
  mismatch. To stay deterministic we ship the matching `.pub` too (a second
  sops secret `ssh.pub`? No—pub is public; instead we let openssh derive from
  the priv at activation, or ship pub via `openssh.knownHosts` consumers).
  **Decision deferred:** simplest is to let openssh generate+keep the `.pub`
  alongside the priv on first boot, and only *publish* the pub into the repo
  once via a one-off `ssh-keygen -y -f <priv>` → commit to
  `secrets/common/ssh/<host>/ssh.pub`. After that, knownHosts consumers use
  `lib.fileContents` of that committed pub. Rotation = regenerate priv+sops,
  re-commit pub.
- Host keys are **per-host** (each host its own pair). The build identity is
  **shared** across hosts (current `remotebuild`); see §5.

### 3.2 knownHosts (kills the `ssh yes` prompt)
On **every** host:
```
services.openssh.knownHosts =
  # one entry per *peer* host, built from committed pubs:
  { builderHost1.publicKey = lib.fileContents ../../secrets/common/ssh/builderHost1/ssh.pub;
    builderHost2.publicKey = lib.fileContents ../../secrets/common/ssh/builderHost2/ssh.pub;
    ...
  };
```
Because `nix.buildMachines` uses these hostnames (after we map them), the SSH
client nix uses trusts them out of the box.

## 4. "Every host is a build host"

Replace the hardcoded `builder1..4` list with an **inventory-driven** list so
enrolling a host == adding it to one list.

- Add (or reuse) an inventory in `constants`:
  ```
  # constants/hosts.nix (new) or existing constants
  buildHosts = {
    hostName = { ip = "10.0.0.x"; port = 42069; systems = ["x86_64-linux"]; speedFactor = 1; };
    ...
  };
  ```
- `modules/common/distributed-builds.nix` generates:
  - `nix.buildMachines = mapAttrsToList (host: h: { ... })` over the inventory, **excluding self** and **excluding woody** (woody sets `distributedBuilds = false` today).
  - `programs.ssh.extraConfig` `Host <host>` blocks from the same inventory.
  - `services.openssh.knownHosts.<host>.publicKey` from `lib.fileContents` of each host's committed pub.
- Each host also needs to **accept** the shared builder identity:
  - `users.users.remotebuild` with `openssh.authorizedKeys.keys = [ the shared build pub ]`.
  - `services.openssh.settings.AllowGroups = [ "remotebuild" ]` (already present in `ssh.nix`).
  - `port`, firewall (`42069`, already open) unchanged.

Scope note: slinky already overrides `buildMachines` to add aarch64 + qemu;
we must preserve its `local.nix` cross-build setup. `woody` stays a pure
builder (not a client). `aarch64` emulation for x86 hosts acting as builders
for arm is handled by `binfmt`/qemu as today — out of scope but must not regress.

## 5. Builder identity (the shared `remotebuild` key)

Today there is one shared `remotebuild` key per host (each host has it in
*its own* `secrets.yaml`, implying it's the same key copied per-host). That
works but scales poorly and couples rotation per-host. Two options:

- **(5a) Shared identity (status quo, minimal):** keep one `remotebuild`
  keypair; every host's `secrets/hosts/<host>/secrets.yaml` stores the same
  `remotebuild/key`+`remotebuild/pub`. Builders trust that single pub via
  `users.users.remotebuild.openssh.authorizedKeys.keys`. Simplest lift; the
  "rotate one key, re-encrypt all files" cost is exactly the rotate script's job.
- **(5b) Per-host build identity:** each host has its *own* build key; other
  hosts list the right pub in knownHosts/authorize. More uniform with §3 but
  more files. Defer unless wanted.

**Recommendation 5a** for now — it is the current shape and only needs
knownHosts (§3.2) + inventory (§4) wired. Flag 5a's "one key, all hosts" as the
rotation-blast-radius note in §6.

## 6. Rotation script: `functions/rotate-secrets.py`

Three operations, one script, host-scoped:
`rotate-secrets.py <subcommand> <host> [--age-key <path>]`

### 6.1 Rotate a genuine secret (sops age key for a host's file) — the hard case
sops-nix reads each host's age private key from a host-local `keyFile`
(e.g. pricklepants: `/var/lib/sops-nix/key.txt`; set via `sops.age.keyFile` in
the host config — confirmed in `hosts/headless/pricklepants/default.nix`).
Rotating means: new age key on the host, new recipient in that host's
`secrets.yaml`, and re-encrypt every `ENC[...]` in that file with the new key.

Script contract (per host):
1. Take a **new age private key** (arg `--age-key <file>` or generate
   `age-keygen -o <tmp>`).
2. Write the new key to the host's configured `keyFile` path inside a deploy
   artifact dir `deploy/<host>/var/lib/sops-nix/key.txt` (to be copied into the
   host's persistent `/var/lib/sops-nix/key.txt`; the script does NOT ssh).
3. Rewrite the `sops.age` block of `secrets/hosts/<host>/secrets.yaml`:
   - replace recipients with the new age pub (`age-keygen` gives the pub line),
   - keep `unencrypted_suffix`, `version`, etc.
4. Re-encrypt the file's `ENC[...]` values to the new recipient using the
   new age key. Contract (pseudo-`sops`, exact flags verified against the
   host's installed `sops` in §8):
   ```sh
   SOPS_AGE_KEY_FILE=<new age key> sops -d secrets/hosts/<host>/secrets.yaml > re.yaml
   SOPS_AGE_KEY_FILE=<new age key> sops -e re.yaml > re.enc
   mv re.enc secrets/hosts/<host>/secrets.yaml
   ``` (If `sops reencrypt --sops-key <newkey>` is supported on the target
   version, prefer it; otherwise the decrypt→re-encrypt round-trip above is
   the canonical, version-agnostic path.)
5. Commit the re-encrypted file + new age pub; print "deploy `<host>` by
   replacing keyFile with `deploy/<host>/var/lib/sops-nix/key.txt`, then rebuild".

### 6.2 Rotate an identity key (host/builder key) — lighter
`rotate-secrets.sh <host> --identity ssh` (or `build`, `borg:<repo>`):
1. `age-keygen`/ssh-keygen for SSH keys → new priv.
2. `sops -d secrets/hosts/<host>/secrets.yaml` ; swap the `<label>.key` value
   with the new priv (re-encrypt via §6.1 step 4 with that file's age key);
3. `ssh-keygen -y -f <newpriv>` → overwrite the committed
   `secrets/common/ssh/<host>/<label>.pub`;
4. commit; redeploy host.

### 6.3 Rotate a nebula cert + key
Nebula certs are X.509, signed by a CA whose key lives on the CA host (not this
host), so this subcommand takes local copies of the CA cert+key:

```
rotate-secrets.py nebula-cert <host> --ca-cert <ca.crt> --ca-key <ca.key> --age-key <host-age-keyfile>
```
1. `nix-shell -p nebula --run 'nebula-cert keygen -out-key <key> -out-pub <pub>'`
2. `nix-shell -p nebula --run 'nebula-cert sign -ca-crt <ca.crt> -ca-key <ca.key> -in-pub <pub> -out-crt <crt> -name <host> -networks 10.0.0.0/24'`
3. Replace `nebula.self_key` + `nebula.self_crt` in the host's sops file
   (re-encrypt preserving existing age recipients).
4. Print: "rebuild <host> to pick up the new cert + key."

The CA cert itself (`nebula.ca_crt`) is shared and rarely rotates; if it does,
that's a separate, heavier operation (regenerate CA → re-sign every host's
cert → redistribute).

### 6.4 Rotation cadence
- Identity keys (SSH host/build/borg, nebula certs): on-demand per host (infrequent).
- sops age key per host: quarterly (calendar) or on personnel/key compromise.

## 7. Borg (the original motivating bug) under the new schema

- Borg *client* key = identity key `<label>="borg:<repo>"`: priv in
  `sops.secrets."borg/<repo>.key"` (as today), pub committed at
  `secrets/common/ssh/<client>/borg:<repo>.pub`.
- `modules/borg-server.nix` `authorizedKeysAppendOnly.<repo>` = pub read via
  `lib.fileContents ../../secrets/common/ssh/<client>/borg:<repo>.pub` instead
  of hand-typed strings.
- Effect: pricklepants' borg pubkey cannot be "forgotten" by woody — enrolling
  the borg client identity auto-wires the server. The
  "borg/woody pubkey missing" class of bug disappears.

## 8. Verification

- `nix flake check` (slow: `flake.lock` is gitignored; ~100-input re-resolve +
  builds all hosts. Pin a lock for CI if this blocks daily dev.)
- `nix eval` on `lib.fileContents` paths + `knownHosts` attr set (synthetic eval
  of one host).
- Live test: new host H → add to `constants.buildHosts` + commit H's pub →
  on existing host E: `nixos-rebuild switch` → `ssh builderH` connects with no
  `yes` (key in knownHosts); E can push a trivial build to H.
- Rotation dry-run on a scratch host (not pricklepants): re-encrypt its file,
  confirm `sops -d` still reads all secrets, confirm `nixos-rebuild switch`
  activates.

## 9. Out of scope (parked, not designed)

- Centralizing `secrets.yaml` into a single shared file: kept per-host on purpose

- The inert `hosts/graphical/zurg/hardware-configuration.nix.old` — already
  deleted (`04a0ffc`).

## 10. Open decisions (mark P for pick during review)

- P1: pub file path (`secrets/common/ssh/<host>/<label>.pub`) vs. inline
  plaintext in `borg-server.nix`/`knownHosts` string — file is preferred for
  host keys (machine-readable); borg server pubs can stay inline OR use the
  file for uniformity. **Default: file for host keys, keep borg inline-as-pub
  but sourced by `lib.fileContents` for consistency once migrated.**
- P2: host key pubs published by `ssh-keygen -y` (one-off) or auto-derived
  each build from the priv via a nixos option — default: one-off commit (pubs
  rarely rotate).
- P3: shared `remotebuild` (5a) vs per-host build identity (5b) — default 5a.
- P4: `constants.buildHosts` lives in `constants/hosts.nix` (new) vs existing
  `constants` — default: new file, host configs already import `constants`.
