# sops-nix key sources

status: current (verified against sops-nix rev 44931708 per flake.lock, nixpkgs
nixos-unstable @ 55bfb4d7, 2026-11-03)

## What

sops-nix's NixOS module (`modules/sops/default.nix`) asserts, whenever at
least one `sops.secrets` entry is declared, that a decryption key source is
configured:

```
cfg.gnupg.home != null
|| cfg.gnupg.sshKeyPaths != [ ]
|| cfg.age.keyFile != null
|| cfg.age.sshKeyPaths != [ ]
```

Failure message: "No key source configured for sops. Either set
services.openssh.enable or services.openssh.generateHostKeys or set
sops.age.keyFile or sops.gnupg.home".

`cfg.age.sshKeyPaths` defaults to `defaultImportKeys "ed25519"` — the ed25519
SSH host key paths from `config.services.openssh.hostKeys` — but only when
`services.openssh.enable || services.openssh.generateHostKeys`
(sops-nix `defaultImportKeys`; nixpkgs `sshd.nix`: `generateHostKeys`
defaults to `services.openssh.enable` but can be set independently to generate
host keys without running sshd). `cfg.gnupg.sshKeyPaths` defaults to the RSA
host keys the same way.

In short, a host satisfies the assertion by setting exactly one of:

* `services.openssh.enable = true` (run sshd; host keys double as sops keys)
* `services.openssh.generateHostKeys = true` (host keys only, no sshd)
* `sops.age.keyFile = "/var/lib/sops-nix/key.txt"` (age key file; must exist,
  or add `sops.age.generateKey = true` to create it)
* `sops.gnupg.home = "/root/.gnupg"` (GPG)

## Per-host configuration in this repo

| Host | Key source | Where |
|------|-----------|-------|
| zurg | `services.openssh.generateHostKeys = true` | `modules/hosts/zurg/configuration.nix` |
| pricklepants | `sops.age.keyFile = "/var/lib/sops-nix/key.txt"` | `modules/hosts/pricklepants/configuration.nix` |
| mrpotatohead, slinky, woody, lenny | `services.openssh.enable = true` | host `configuration.nix` |
| hosts importing `persistence` | `sops.age.sshKeyPaths` over persisted host keys in `/nix/persist/etc/ssh/` | `modules/services/persistence.nix` |

zurg imports the `sops` aspect (`modules/system/sops.nix`, which imports
`sops-nix.nixosModules.sops` and sets `sops.defaultSopsFile`) and the `nebula`
aspect, which unconditionally declares `sops.secrets."nebula/*"`. With
`services.openssh.enable` left disabled (zurg is a laptop), no key source was
configured and evaluation of `system.build.toplevel` failed with the assertion
above.

Fix applied 2026-11-03: `services.openssh.generateHostKeys = true;` in
`modules/hosts/zurg/configuration.nix` — generates the ed25519 host key (via
`sshd-keygen.service`) without starting sshd, making `sops.age.sshKeyPaths`
non-empty. Verified with `nix eval .#nixosConfigurations.zurg.config.system.build.toplevel`,
which now produces a valid system derivation (previously aborted on the
assertion).

Operational note: `sops-install-secrets` decrypts at activation using the
configured keys, so the sops files must actually have been encrypted to a key
zurg holds (host key age1ssh recipient, or an age key file). zurg's ssh host
public key is tracked at `secrets/common/ssh/zurg/ssh.pub` (added 2026-10-22);
the matching private key is expected on zurg (existing deployment) or
generated by `sshd-keygen.service`.

## Secrets layout

* `secrets/shared.yaml` — shared secrets (telegram, nebula ca_crt, …);
  `sops.defaultSopsFile` for hosts importing the `sops` aspect.
* `secrets/hosts/<host>/secrets.yaml` — host-scoped secrets (nebula host
  cert/key, …); referenced via per-secret `sopsFile`.
* `secrets/common/ssh/<host>/ssh.pub` — that host's ssh host public key.
