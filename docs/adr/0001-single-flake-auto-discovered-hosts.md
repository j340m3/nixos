# ADR-0001: Auto-discovered host folders in a single flake

**Date**: 2025-07-08
**Status**: accepted (backfilled 2026-10-15)
**Deciders**: j340m3

## Context

The repo started (2024-12) with hand-listed `nixosConfigurations` in
`flake.nix`. Adding a host meant writing another `nixosSystem` block. The
same auto-discovery pattern appears in other public nixos-flake configs and
promised near-zero host onboarding: when installing NixOS, copy
`/etc/nixos` into a new folder under `hosts/`, rename `configuration.nix`
to `default.nix`, and the host exists.

## Decision

Migrate to auto-discovery: every folder under `hosts/` is one
`nixosConfiguration`, generated by a small `readDir` + `mkHost` loop in
`flake.nix`. (The later split into `hosts/graphical/` and `hosts/headless/`
is recorded in ADR-0011.)

## Alternatives Considered

### Keep hand-listed nixosConfigurations (status quo)
- **Pros**: explicit and greppable; already worked.
- **Cons**: every host add touches `flake.nix`; more boilerplate than the
  install-time copy flow.
- **Why not**: the loop is a few lines and removes the per-host boilerplate.

## Consequences

### Positive
- Adding a host = create a folder, update `HOSTS.md`. No flake edit.
- One `nix flake update` moves the whole fleet's inputs together.

### Negative
- A stray folder under `hosts/` becomes a configuration; eval checks catch
  breakage, but naming mistakes surface late.

### Risks
- Folder name is the host name — rename = config rename; `HOSTS.md` is the
  human map.
